# DFR0002: アーキテクチャ参照違反（モジュール間参照）

| プロパティ | 値 |
|---|---|
| 規則 ID | DFR0002 |
| タイトル | アーキテクチャ参照違反（モジュール間参照） |
| 既定の重大度 | Warning |
| 修正が破壊的か非破壊的か | 破壊的（公開メンバーのシグネチャを変更する場合） / 非破壊的（実装内部のみを変更する場合） |
| コード修正 | なし |

## 原因

モジュール（クラス・インターフェース）間の依存関係が不適切です。
D3Fragments では Clean Architecture ベースのアーキテクチャを採用していますが、 DFR0002 が検出される箇所では不適切な依存関係が実装されています。

具体的には以下の依存関係（クラス・インターフェースの参照・利用）が違反として報告されます。モジュールレイヤー名、およびモジュールレイヤーの判定方法に関する詳細は[モジュールレイヤー](../architecture.md#モジュールレイヤー)を参照してください。

| 参照元モジュールレイヤー名 | 参照先モジュールレイヤー名 |
| :------------------------- | :------------------------- |
| Presentation_Controller    | Application_RequestHandler, Application_DomainEventHandler, Domain_RepositoryInterface, Domain_DomainRule, Infrastructure_* |
| Application_Request, Application_RequestHandler, Application_RequestExecutor, Application_DomainEventHandler | Presentation_Controller, Infrastructure_RepositoryImplementation |
| Domain_Entity, Domain_ValueObject | Application_Request, Application_RequestHandler, Application_RequestExecutor, Application_DomainEventHandler, Presentation_Controller, Domain_RepositoryInterface, Infrastructure_RepositoryImplementation |
| Domain_RepositoryInterface | Application_Request, Application_RequestHandler, Application_RequestExecutor, Application_DomainEventHandler, Presentation_Controller, Infrastructure_RepositoryImplementation |
| Domain_DomainRule          | Application_Request, Application_RequestHandler, Application_RequestExecutor, Application_DomainEventHandler, Presentation_Controller, Domain_RepositoryInterface, Infrastructure_RepositoryImplementation |

`Infrastructure_*` は `Infrastructure_RepositoryImplementation` と `Infrastructure_Other` を表します。

参照元のクラス・インターフェースの宣言内で、参照先のクラス・インターフェースが以下のいずれかの形で使用されている場合に違反となります。

- 基底クラス・実装インターフェース
- フィールド・プロパティ・イベントの型、メソッドの戻り値・引数の型（コンストラクタ引数による注入を含む）
- ローカル変数の型、型パターン・キャストの型、`typeof` の対象
- 型引数（例：`List<IBookRepository>`、`IEnumerable<BookRepository>`）
- メンバー（メソッド・プロパティ・フィールド等）の呼び出し・参照、インスタンスの生成
- 属性

ただし、`nameof` の中での参照は違反となりません。

この規則は参照元/先アセンブリに `ArchitectureLayerAttribute` が設定されている場合にのみ検証されます。 `ArchitectureLayerAttribute` が未設定のアセンブリから/への参照は無条件に許可されます。

参照元・参照先のどちらかのモジュールレイヤーが `*_Other`、または `Other`（複数のアーキテクチャ層を持つアセンブリで、アーキテクチャ層が特定できないその他クラス）の場合、上記の表に記載がない限り違反とはなりません。
例えば、ドメイン層＋アプリケーション層のアセンブリにおいて、エンティティがアプリケーション層の補助クラス（`Other` と判定されるクラス）を参照していても、本規則では検知できません。

## 規則の説明

D3Fragments では Clean Architecture ベースのアーキテクチャを採用しています。
Clean Architecture ではレイヤー間の依存関係にルールが定められています。
システムの保守性を維持するため、レイヤー間の依存関係ルールを遵守することが推奨されます。

アセンブリ（プロジェクト）レベルでの依存関係の検証は [DFR0001: アーキテクチャ参照違反（プロジェクト間参照）](DFR0001.md) により実施します。
本規則ではアセンブリレベルでの検証では網羅できない、より細かい粒度での依存関係の検証を行います。
複数のアーキテクチャ層を持つアセンブリ内の、アーキテクチャ層をまたぐ依存関係も本規則で検証されます。

`Domain_DomainRule`（`IDomainRule<TContext>` の実装）からリポジトリインターフェースへの参照を禁止しているのは、ドメインルールを外部のI/Oに依存しない純粋な判定処理に保つためです。判定に必要なデータは、呼び出し元でリポジトリから取得し `TContext` として渡してください。

`Presentation_Controller` から `Domain_DomainRule` への参照を禁止しているのは、ドメインルールの評価はドメインモデルとアプリケーション層の責務であり、プレゼンテーション層の責務ではないためです。ドメインルールはリクエストハンドラから呼び出してください。その他のドメイン層のクラス（ドメインサービス等）のコントローラへの注入は [DFR0011](DFR0011.md) で検出します。

## 違反の修正方法

この規則違反を修正するためには、許可されていないクラス・インターフェースへの参照を削除する必要があります。

例えば、コントローラからリクエストハンドラやリポジトリを直接利用している場合は、`IRequestExecutor<TRequest, TResponse>` を経由してアプリケーション層の処理を呼び出してください。

## 例

```csharp
public class BooksController(IBookshelfRepository repository) : ControllerBase
{
    // Violates DFR0002: Presentation_Controller から Domain_RepositoryInterface を参照しています
    [HttpGet("{id}")]
    public async Task<IActionResult> Get(UuidV7 id, CancellationToken cancellationToken)
        => Ok(await repository.FindAsync(id, cancellationToken));
}
```

```csharp
public class BooksController(IRequestExecutor<GetBookshelfQuery, BookshelfDto> executor) : ControllerBase
{
    // Does not violate DFR0002
    [HttpGet("{id}")]
    public async Task<IActionResult> Get(UuidV7 id, CancellationToken cancellationToken)
        => Ok(await executor.ExecuteAsync(new GetBookshelfQuery(id), cancellationToken));
}
```

## 警告を抑制する状況

一般に、この規則による警告は抑制しないでください。

## 警告を抑制する

単一の違反を抑制するだけの場合は、ソース ファイルにプリプロセッサ ディレクティブを追加して無効にしてから、規則をもう一度有効にします。

```csharp
#pragma warning disable DFR0002
// 規則に違反するコード
#pragma warning restore DFR0002
```

ファイル、フォルダー、プロジェクトの規則を無効にするには、その重要度を `none` に設定し、[設定ファイル](https://learn.microsoft.com/ja-jp/dotnet/fundamentals/code-analysis/configuration-files) で適用します。

```ini
[*.cs]
dotnet_diagnostic.DFR0002.severity = none
```
