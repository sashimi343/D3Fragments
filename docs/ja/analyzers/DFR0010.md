# DFR0010: 値オブジェクトは公開セッターをもつべきではありません

| プロパティ | 値 |
|---|---|
| 規則 ID | DFR0010 |
| タイトル | 値オブジェクトは公開セッターをもつべきではありません |
| 既定の重大度 | Warning |
| 修正が破壊的か非破壊的か | 破壊的 |
| コード修正 | あり（プロパティのみ） |

## 原因

`D3Fragments.ValueObjectBase<TSelf, TPrimitive>` クラスを直接、または間接的に継承した型、または `D3Fragments.IValueObject<TSelf, TPrimitive>` インターフェースを直接、または間接的に実装した型（クラス・構造体・レコード）において、以下のいずれかのメンバーが宣言されています。

- アクセシビリティが `public` / `internal` / `protected internal` の `set` アクセサーまたは `init` アクセサーをもつプロパティ
- アクセシビリティが `public` / `internal` / `protected internal` で、`readonly` ではないフィールド（`const` を除く）

アクセサーのアクセシビリティの扱い、対象外となるメンバー、違反の報告箇所は [DFR0003](DFR0003.md) と同じです。
位置指定レコードのパラメーターから生成されるプロパティは `init` アクセサーをもつため、違反となります。

本規則はアセンブリのアーキテクチャ層の設定（`ArchitectureLayerAttribute`）に関係なく検証されます。

## 規則の説明

値オブジェクトは不変であるべきです。
値オブジェクトの値を生成後に変更できると、値オブジェクトを共有している他のオブジェクトの状態まで意図せず変わってしまいます。
また、`Create` などのファクトリーメソッドで行っている値の検証を経由せずに、不正な値を設定できてしまいます。

## 違反の修正方法

セッターを削除して取得専用のプロパティにするか、セッターのアクセシビリティを `private` に変更してください。フィールドの場合は `readonly` にしてください。
値を変更したい場合は、新しい値オブジェクトを生成してください。

コード修正では、プロパティのセッター（`set` / `init`）を `private set` に変更します。

## 例

```csharp
public sealed class Email : ValueObjectBase<Email, string>, IValueObject<Email, string>
{
    // Violates DFR0010
    public string Domain { get; set; }

    ...
}
```

```csharp
public sealed class Email : ValueObjectBase<Email, string>, IValueObject<Email, string>
{
    // Does not violate DFR0010
    public string Domain { get; }

    ...
}
```

## 警告を抑制する状況

一般に、この規則による警告は抑制しないでください。

## 警告を抑制する

単一の違反を抑制するだけの場合は、ソース ファイルにプリプロセッサ ディレクティブを追加して無効にしてから、規則をもう一度有効にします。

```csharp
#pragma warning disable DFR0010
// 規則に違反するコード
#pragma warning restore DFR0010
```

ファイル、フォルダー、プロジェクトの規則を無効にするには、その重要度を `none` に設定し、[設定ファイル](https://learn.microsoft.com/ja-jp/dotnet/fundamentals/code-analysis/configuration-files) で適用します。

```ini
[*.cs]
dotnet_diagnostic.DFR0010.severity = none
```
