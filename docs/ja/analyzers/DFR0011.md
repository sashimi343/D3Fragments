# DFR0011: コントローラはドメイン層のクラスをコンストラクタで注入すべきではありません

| プロパティ | 値 |
|---|---|
| 規則 ID | DFR0011 |
| タイトル | コントローラはドメイン層のクラスをコンストラクタで注入すべきではありません |
| 既定の重大度 | Warning |
| 修正が破壊的か非破壊的か | 非破壊的 |
| コード修正 | なし |

## 原因

コントローラ（モジュールレイヤーが `Presentation_Controller` のクラス）のコンストラクタ引数の型に、モジュールレイヤーが `Domain_Other` のクラス・インターフェースが指定されています。
モジュールレイヤー名、およびモジュールレイヤーの判定方法に関する詳細は[モジュールレイヤー](../architecture.md#モジュールレイヤー)を参照してください。

以下の点に注意してください。

- プライマリコンストラクタを含む、すべてのインスタンスコンストラクタの引数が対象です。
- 検出するのは引数の型そのものが `Domain_Other` の場合のみです。型引数（例：`IEnumerable<IPriceCalculator>`）は対象外です。
- コンストラクタ引数以外（アクションメソッドの引数・ローカル変数・メンバーの参照等）での `Domain_Other` の利用は違反となりません。
- `Domain_Other` と判定されるのは、ドメイン層のみを持つアセンブリのクラス・インターフェースです。複数のアーキテクチャ層を持つアセンブリのクラス・インターフェースは `Other` と判定されるため、本規則では検知できません。

この規則は参照元/先アセンブリに `ArchitectureLayerAttribute` が設定されている場合にのみ検証されます。

## 規則の説明

コントローラの責務は、HTTPリクエストを受け取りアプリケーション層の処理（`IRequestExecutor<TRequest, TResponse>`）を呼び出すことです。
コントローラがドメインサービス等のドメイン層のクラスを注入して呼び出すと、ドメインロジックの組み立てがプレゼンテーション層に漏れ出し、アプリケーション層のトランザクション制御やPipeline Behaviorも経由しなくなります。

`Domain_Other` には、ドメインサービスのほか、`TypeSafeEnum<TSelf, TKey>` の派生クラス、列挙型、エラー定義なども含まれます。
これらはDTOの型や分岐で正当に利用されるため、本規則は参照全般ではなくDIによる注入（コンストラクタ引数）に限って検出します。DIで注入される `Domain_Other` はドメインサービスとみなせるためです。

ドメイン層のその他のクラスの参照は [DFR0002: アーキテクチャ参照違反（モジュール間参照）](DFR0002.md) により検証します（リポジトリインターフェース・ドメインルールの参照は、コンストラクタ引数を含めDFR0002で検出されます）。

## 違反の修正方法

ドメインサービスの呼び出しをリクエストハンドラへ移動し、コントローラからは `IRequestExecutor<TRequest, TResponse>` を経由して呼び出してください。

## 例

```csharp
public class BooksController(IShippingFeeCalculator calculator) : ControllerBase
{
    // Violates DFR0011
    [HttpGet("{id}/shipping-fee")]
    public int GetShippingFee(UuidV7 id, int weight) => calculator.Calculate(weight);
}
```

```csharp
public class BooksController(IRequestExecutor<GetShippingFeeQuery, int> executor) : ControllerBase
{
    // Does not violate DFR0011
    [HttpGet("{id}/shipping-fee")]
    public Task<int> GetShippingFee(UuidV7 id, int weight, CancellationToken cancellationToken)
        => executor.ExecuteAsync(new GetShippingFeeQuery(id, weight), cancellationToken);
}
```

## 警告を抑制する状況

一般に、この規則による警告は抑制しないでください。

ドメイン層のみを持つアセンブリに、DIで注入するがドメインサービスではないクラス（ドメイン層に置いた設定値クラス等）を定義している場合は、警告を抑制してもかまいません。

## 警告を抑制する

単一の違反を抑制するだけの場合は、ソース ファイルにプリプロセッサ ディレクティブを追加して無効にしてから、規則をもう一度有効にします。

```csharp
#pragma warning disable DFR0011
// 規則に違反するコード
#pragma warning restore DFR0011
```

ファイル、フォルダー、プロジェクトの規則を無効にするには、その重要度を `none` に設定し、[設定ファイル](https://learn.microsoft.com/ja-jp/dotnet/fundamentals/code-analysis/configuration-files) で適用します。

```ini
[*.cs]
dotnet_diagnostic.DFR0011.severity = none
```
