# DFR0016: リクエスト型は ICommand と IQuery のどちらか一方を実装してください

| プロパティ | 値 |
|---|---|
| 規則 ID | DFR0016 |
| タイトル | リクエスト型は ICommand と IQuery のどちらか一方を実装してください |
| 既定の重大度 | Warning |
| 修正が破壊的か非破壊的か | 非破壊的 |
| コード修正 | なし |

## 原因

`IRequest<TResponse>` を実装した非抽象のクラス・構造体（レコードを含む）が、`ICommand` と `IQuery` のどちらも実装していないか、両方を実装しています。

以下の点に注意してください。

- `ICommand` を継承する `ITransactionalCommand` を実装している場合は、`ICommand` を実装しているものとして扱います。
- 抽象型とインターフェースは対象外です。派生型で `ICommand<TResponse>` または `IQuery<TResponse>` を実装してください。

## 規則の説明

`UnitOfWorkBehavior` は、`IQuery` を実装していないリクエストを Command として扱い、Handler の実行後に変更を保存します。
そのため、`IRequest<TResponse>` を直接実装したリクエストは Command と同じ動作になり、型を見ても副作用の有無が分かりません。
また、`ICommand` と `IQuery` の両方を実装したリクエストは `IQuery` として扱われ、変更が保存されません。

`AddD3FragmentsApplication` もこのようなリクエストの Handler を登録する際に `InvalidOperationException` をスローします。この規則は、同じ問題を実行前に検出するためのものです。

## 違反の修正方法

データを変更するリクエストは `ICommand<TResponse>` を、変更しないリクエストは `IQuery<TResponse>` を実装してください。

## 例

```csharp
// Violates DFR0016
public sealed record GetShelfQuery(UuidV7 Id) : IRequest<Shelf?>;

// Violates DFR0016
public sealed record AddShelfCommand(string Name) : ICommand<UuidV7>, IQuery<UuidV7>;
```

```csharp
// Does not violate DFR0016
public sealed record GetShelfQuery(UuidV7 Id) : IQuery<Shelf?>;

// Does not violate DFR0016
public sealed record AddShelfCommand(string Name) : ICommand<UuidV7>;
```

## 警告を抑制する状況

この規則による警告は抑制しないでください。違反したリクエストの Handler は、`AddD3FragmentsApplication` での登録時に例外となります。

## 警告を抑制する

単一の違反を抑制するだけの場合は、ソース ファイルにプリプロセッサ ディレクティブを追加して無効にしてから、規則をもう一度有効にします。

```csharp
#pragma warning disable DFR0016
// 規則に違反するコード
#pragma warning restore DFR0016
```

ファイル、フォルダー、プロジェクトの規則を無効にするには、その重要度を `none` に設定し、[設定ファイル](https://learn.microsoft.com/ja-jp/dotnet/fundamentals/code-analysis/configuration-files) で適用します。

```ini
[*.cs]
dotnet_diagnostic.DFR0016.severity = none
```
