# DFR0013: エンティティに対して Update・Attach を呼び出さないでください

| プロパティ | 値 |
|---|---|
| 規則 ID | DFR0013 |
| タイトル | エンティティに対して Update・Attach を呼び出さないでください |
| 既定の重大度 | Warning |
| 修正が破壊的か非破壊的か | 非破壊的 |
| コード修正 | なし |

## 原因

`D3Fragments.EntityBase<TId>` クラスを直接、または間接的に継承したクラス（エンティティ）を対象として、EF Core の以下のメソッドが呼び出されています。

| 型 | メソッド |
|---|---|
| `DbContext`（およびその派生クラス） | `Update`、`UpdateRange`、`Attach`、`AttachRange` |
| `DbSet<TEntity>` | `Update`、`UpdateRange`、`Attach`、`AttachRange` |

以下の点に注意してください。

- 対象の型は、`DbSet<TEntity>` では `TEntity`、`DbContext` のジェネリックメソッドでは型引数、非ジェネリックメソッド（`object` 型の引数）では実引数の静的な型（配列・コレクションの場合は要素の型）で判定します。静的な型が `object` の場合は検知できません。
- エンティティ以外の型（キーをDB側で採番するテーブル等）に対する呼び出しは違反となりません。
- `ExecuteUpdate`・`ExecuteDelete` は対象外です。
- エンティティに定義された同名のメソッド（例：`order.Update(...)`）は対象外です。

この規則は、呼び出し元のアセンブリに `ArchitectureLayerAttribute` が設定されている場合にのみ検証されます。

## 規則の説明

D3Fragments のエンティティは、コンストラクタで ID（UUIDv7）を採番するため、生成された時点でキーが設定済みです。
EF Core の `Update`・`Attach` は、キーが設定済みのエンティティを既存の行として扱うため、以下の問題が発生します。

- 新しく追加した子エンティティが INSERT ではなく UPDATE され、`DbUpdateConcurrencyException` が発生する（`Update`）
- 新しく追加した子エンティティが `Unchanged` として扱われ、INSERT されない（`Attach`）

D3Fragments では、集約は変更追跡を有効にしたまま取得し、取得済みの集約への変更は Unit of Work が保存します。そのため `Update`・`Attach` を呼び出す必要はありません。

## 違反の修正方法

`Update`・`Attach` の呼び出しを削除してください。

- 既存の集約を変更する場合は、リポジトリで取得した（変更追跡中の）集約のメソッドを呼び出してください。
- 新しい集約を追加する場合は、リポジトリの `Add` を使用してください。

## 例

```csharp
public sealed class ShelfRepository(AppDbContext dbContext) : RepositoryBase<AppDbContext, Shelf>(dbContext), IShelfRepository
{
    // Violates DFR0013
    public void Save(Shelf shelf) => DbContext.Update(shelf);
}
```

```csharp
public sealed class RenameShelfHandler(IShelfRepository shelves) : IRequestHandler<RenameShelf, UuidV7>
{
    public async Task<UuidV7> HandleAsync(RenameShelf command, CancellationToken cancellationToken)
    {
        var shelf = await shelves.FindAsync(command.Id, cancellationToken) ?? throw new EntityNotFoundException(nameof(Shelf));

        // Does not violate DFR0013: the tracked aggregate is saved by the Unit of Work
        shelf.Rename(command.Name);
        return shelf.Id;
    }
}
```

## 警告を抑制する状況

一般に、この規則による警告は抑制しないでください。

## 警告を抑制する

単一の違反を抑制するだけの場合は、ソース ファイルにプリプロセッサ ディレクティブを追加して無効にしてから、規則をもう一度有効にします。

```csharp
#pragma warning disable DFR0013
// 規則に違反するコード
#pragma warning restore DFR0013
```

ファイル、フォルダー、プロジェクトの規則を無効にするには、その重要度を `none` に設定し、[設定ファイル](https://learn.microsoft.com/ja-jp/dotnet/fundamentals/code-analysis/configuration-files) で適用します。

```ini
[*.cs]
dotnet_diagnostic.DFR0013.severity = none
```
