# DFR0020: リポジトリの即時の操作は ExecuteImmediateAsync の中で実行してください

| プロパティ | 値 |
|---|---|
| 規則 ID | DFR0020 |
| タイトル | リポジトリの即時の操作は ExecuteImmediateAsync の中で実行してください |
| 既定の重大度 | Warning |
| 修正が破壊的か非破壊的か | 非破壊的 |
| コード修正 | なし |

## 原因

リポジトリの実装クラス（モジュールレイヤーが `Infrastructure_RepositoryImplementation` のクラス）で、データベースに即時に実行される EF Core の以下のメソッドが、`RepositoryBase.ExecuteImmediateAsync` に渡すラムダの外で呼び出されています。
モジュールレイヤー名、およびモジュールレイヤーの判定方法に関する詳細は[モジュールレイヤー](../guide/01-architecture.md#モジュールレイヤー)を参照してください。

- `ExecuteUpdate`・`ExecuteUpdateAsync`
- `ExecuteDelete`・`ExecuteDeleteAsync`
- `Database.ExecuteSql`・`ExecuteSqlRaw`・`ExecuteSqlInterpolated` と、それぞれの非同期版

以下の点に注意してください。

- リポジトリ以外のクラス（クエリサービス等）での呼び出しは違反となりません。
- `ExecuteImmediateAsync` に渡すラムダの中（その中の入れ子のラムダを含む）での呼び出しは違反となりません。ラムダから呼び出した別のメソッドの中での呼び出しは、違反として報告されます。
- 共通の拡張メソッド等の内部で呼び出している場合は検知できません。

この規則は、呼び出し元のアセンブリに `ArchitectureLayerAttribute` が設定されている場合にのみ検証されます。

## 規則の説明

D3Fragments では、追跡中の変更は Handler の終了後に `UnitOfWorkBehavior` が保存します。
一方、即時の操作は Handler の途中、呼び出した時点で実行されます。このため、次の問題が起きます。

- 順序が入れ替わる：同じ Command で追加・変更した集約は、即時の操作の時点ではまだ保存されていません。「変更を保存してから、その結果を使う一括の SQL を実行する」処理が正しく動きません。
- トランザクションの外では、その場で確定する：`ITransactionalCommand` でない Command では、即時の操作は自動 Commit により即座に確定します。Handler がその後で例外をスローしても戻らず、「Command が失敗したら何も保存されない」という前提が崩れます。

`ExecuteImmediateAsync` は、トランザクションの中であることを確認し（トランザクションの外では `InvalidOperationException` をスローします）、未保存の変更を保存してから操作を実行します。
保存した変更は Commit されず、Command が失敗した場合はトランザクションとともにロールバックされます。

## 違反の修正方法

即時の操作を `ExecuteImmediateAsync` に渡すラムダの中で呼び出し、その操作を使う Command に `ITransactionalCommand` を実装してください。

## 例

```csharp
public sealed class ReservationRepository(LibraryDbContext dbContext)
    : RepositoryBase<LibraryDbContext, Reservation>(dbContext), IReservationRepository
{
    // Violates DFR0020
    public Task<int> DeleteExpiredAsync(DateOnly today, CancellationToken cancellationToken) =>
        Set.Where(x => x.HoldUntil < today).ExecuteDeleteAsync(cancellationToken);
}
```

```csharp
public sealed class ReservationRepository(LibraryDbContext dbContext)
    : RepositoryBase<LibraryDbContext, Reservation>(dbContext), IReservationRepository
{
    // Does not violate DFR0020
    public Task<int> DeleteExpiredAsync(DateOnly today, CancellationToken cancellationToken) =>
        ExecuteImmediateAsync(ct => Set.Where(x => x.HoldUntil < today).ExecuteDeleteAsync(ct), cancellationToken);
}
```

## 警告を抑制する状況

一般に、この規則による警告は抑制しないでください。

## 警告を抑制する

単一の違反を抑制するだけの場合は、ソース ファイルにプリプロセッサ ディレクティブを追加して無効にしてから、規則をもう一度有効にします。

```csharp
#pragma warning disable DFR0020
// 規則に違反するコード
#pragma warning restore DFR0020
```

ファイル、フォルダー、プロジェクトの規則を無効にするには、その重要度を `none` に設定し、[設定ファイル](https://learn.microsoft.com/ja-jp/dotnet/fundamentals/code-analysis/configuration-files) で適用します。

```ini
[*.cs]
dotnet_diagnostic.DFR0020.severity = none
```
