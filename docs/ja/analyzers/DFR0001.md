# DFR0001: アーキテクチャ参照違反（プロジェクト間参照）

| プロパティ | 値 |
|---|---|
| 規則 ID | DFR0001 |
| タイトル | アーキテクチャ参照違反（プロジェクト間参照） |
| 既定の重大度 | Warning |
| 修正が破壊的か非破壊的か | 非破壊的 |
| コード修正 | なし |

## 原因

プロジェクト間の依存関係が不適切です。抽象度の高いアセンブリは抽象度の低いアセンブリに依存すべきではありません。
レイヤー間の依存関係の許可/禁止ルールは以下のとおりです。

| from / to      | Presentation | Application | Domain | Infrastructure |
| :------------- | :----------: | :---------: | :----: | :------------: |
| Presentation   | ○            | ○           | ○      | ※1             |
| Application    | ×            | ○           | ○      | ×              |
| Domain         | ×            | ×           | ○      | ×              |
| Infrastructure | ×            | ○           | ○      | ○              |

※1: DIコンテナへの登録処理での参照を想定しています。DIコンテナ登録以外（コントローラ等）からの Infrastructure 層の利用は [DFR0002](DFR0002.md) により警告されます。

コンパイル時に参照されるアセンブリ（プロジェクト参照・パッケージ参照によるもの。推移的な参照を含む）の中に、禁止された依存関係のアセンブリが含まれる場合、その参照元 (from) プロジェクトにてこの違反が報告されます。
違反はソースコード上の位置を持たないプロジェクト単位の診断として報告されます。

この規則は参照元/先アセンブリに `ArchitectureLayerAttribute` が設定されている場合にのみ検証されます。 `ArchitectureLayerAttribute` が未設定のアセンブリから/への参照は無条件に許可されます。

参照元/先のアセンブリが複数のアーキテクチャ層を持つ場合、参照元のいずれかのアーキテクチャ層から参照先のいずれかのアーキテクチャ層への依存が許可（○）されていれば、参照は許可されます。
このため、複数のアーキテクチャ層を持つアセンブリでは、本規則によるアーキテクチャ層間の検証は限定的になります。また、同一アセンブリ内のアーキテクチャ層間の依存関係は本規則では検証されません。これらは [DFR0002](DFR0002.md) により、モジュールレイヤー単位で部分的に検証されます。

## 規則の説明

D3Fragments は Clean Architecture をもとにしたアーキテクチャを前提にしています。
このアーキテクチャでは、依存の向きを外側の層から内側の層（ドメイン層）への一方向に限ります。
この向きを守ると、ドメイン層とアプリケーション層のコードが EF Core や ASP.NET Core に依存しません。
DB へのアクセス方法や画面の実装を変えても、これらの層を書き換えずに済みます。

## 違反の修正方法

この規則違反を修正するには、許可されていないプロジェクト参照・パッケージ参照を csproj から削除する必要があります。
推移的な参照によって違反が報告されている場合は、その参照を持ち込んでいる直接参照を見直してください。

## 例

```csharp
// MyApp.Domain プロジェクトの AssemblyInfo.cs
[assembly: ArchitectureLayer(ArchitectureLayerType.Domain)]

// MyApp.Application プロジェクトの AssemblyInfo.cs
[assembly: ArchitectureLayer(ArchitectureLayerType.Application)]
```

```xml
<!-- MyApp.Domain.csproj -->
<ItemGroup>
  <!-- Violates DFR0001: Domain から Application への参照は禁止されています -->
  <ProjectReference Include="..\MyApp.Application\MyApp.Application.csproj" />
</ItemGroup>
```

## 警告を抑制する状況

一般に、この規則による警告は抑制しないでください。

## 警告を抑制する

この規則違反はソースコード上の位置を持たないため、ソースファイルへのプリプロセッサディレクティブの追加や、`.editorconfig` のファイル単位の設定では抑制できません。
プロジェクトの規則を無効にするには、csproj の `NoWarn` に規則 ID を追加します。

```xml
<PropertyGroup>
  <NoWarn>$(NoWarn);DFR0001</NoWarn>
</PropertyGroup>
```

または、[グローバル AnalyzerConfig ファイル](https://learn.microsoft.com/ja-jp/dotnet/fundamentals/code-analysis/configuration-files#global-analyzerconfig) で重要度を `none` に設定します。

```ini
is_global = true
dotnet_diagnostic.DFR0001.severity = none
```
