# DFR0018: Handler から Command を実行するときは IIsolatedRequestExecutor を使ってください

| プロパティ | 値 |
|---|---|
| 規則 ID | DFR0018 |
| タイトル | Handler から Command を実行するときは IIsolatedRequestExecutor を使ってください |
| 既定の重大度 | Warning |
| 修正が破壊的か非破壊的か | 非破壊的 |
| コード修正 | なし |

## 原因

Command の Handler（`ICommand` を実装したリクエストの `IRequestHandler<TRequest, TResponse>` の実装）または Commit 前のドメインイベントハンドラ（`IBeforeCommitDomainEventHandler<TEvent>` の実装）のコンストラクタ引数に、Command を実行する `IRequestExecutor<TRequest, TResponse>` が指定されています。

以下の点に注意してください。

- プライマリコンストラクタを含む、すべてのインスタンスコンストラクタの引数が対象です。
- `IRequestExecutor<TRequest, TResponse>` を実装したクラス（`RequestExecutor<TRequest, TResponse>` など）も対象です。`IIsolatedRequestExecutor<TRequest, TResponse>` とその実装は対象外です。
- 実行するリクエストが Query の場合は対象外です。`UnitOfWorkBehavior` は Query の変更を保存しないためです。
- 実行するリクエストの型が型パラメータの場合は、Command か Query かを判定できないため対象外です。
- Commit 後のドメインイベントハンドラ（`IAfterCommitDomainEventHandler<TEvent>` の実装）は対象外です。Commit が済んでいるため、同じスコープで別の Command を実行できます。
- Query の Handler が Command を実行する場合は、この規則ではなく [DFR0019](DFR0019.md) で報告します。

この規則は、アセンブリに `ArchitectureLayerAttribute` が設定されている場合にのみ検証されます。

## 規則の説明

`IRequestExecutor<TRequest, TResponse>` は、呼び出し元と同じ DI スコープで Command を実行します。
Handler の中から同じスコープで別の Command を実行すると、`DbContext` を呼び出し元と共有するため、内側の Command の保存が、呼び出し元のまだ保存していない変更まで保存してしまいます。
呼び出し元がトランザクションの中（`ITransactionalCommand`）で実行されている場合は、トランザクションが入れ子になるため例外になります。

別の Command の変更を呼び出し元と独立して確定させたい場合は、新しい DI スコープで実行する `IIsolatedRequestExecutor<TRequest, TResponse>` を使います。
詳しくは [Pipeline とトランザクション](../guide/04-application/02-pipeline-and-transactions.md#別のスコープで-command-を実行する) を参照してください。

## 違反の修正方法

コンストラクタ引数の型を `IIsolatedRequestExecutor<TRequest, TResponse>` に変更してください。
別の Command の変更を呼び出し元と同じトランザクションで保存したい場合は、Command を実行せずに、その処理を Handler の中に書くか、ドメインイベントと Commit 前のハンドラを使ってください。

## 例

```csharp
public sealed class PlaceOrderCommandHandler(IRequestExecutor<RecordAuditCommand, Result> recordAudit)
    : IRequestHandler<PlaceOrderCommand, Result>
{
    // Violates DFR0018
}
```

```csharp
public sealed class PlaceOrderCommandHandler(IIsolatedRequestExecutor<RecordAuditCommand, Result> recordAudit)
    : IRequestHandler<PlaceOrderCommand, Result>
{
    // Does not violate DFR0018
}
```

## 警告を抑制する状況

この規則による警告は抑制しないでください。

## 警告を抑制する

単一の違反を抑制するだけの場合は、ソース ファイルにプリプロセッサ ディレクティブを追加して無効にしてから、規則をもう一度有効にします。

```csharp
#pragma warning disable DFR0018
// 規則に違反するコード
#pragma warning restore DFR0018
```

ファイル、フォルダー、プロジェクトの規則を無効にするには、その重要度を `none` に設定し、[設定ファイル](https://learn.microsoft.com/ja-jp/dotnet/fundamentals/code-analysis/configuration-files) で適用します。

```ini
[*.cs]
dotnet_diagnostic.DFR0018.severity = none
```
