# DFR0012: Pipeline Behavior 以外で保存・トランザクションを操作しないでください

| プロパティ | 値 |
|---|---|
| 規則 ID | DFR0012 |
| タイトル | Pipeline Behavior 以外で保存・トランザクションを操作しないでください |
| 既定の重大度 | Warning |
| 修正が破壊的か非破壊的か | 非破壊的 |
| コード修正 | なし |

## 原因

以下のモジュールレイヤー以外のクラスで、変更の保存・トランザクションの操作を行うメソッドが呼び出されています。
モジュールレイヤー名、およびモジュールレイヤーの判定方法に関する詳細は[モジュールレイヤー](../guide/01-architecture.md#モジュールレイヤー)を参照してください。

- `Application_PipelineBehavior`（`IPipelineBehavior<TRequest, TResponse>` の実装）
- `Infrastructure_DbContext`（`DbContext` の派生クラス）
- `Infrastructure_UnitOfWork`（`IUnitOfWork` の実装）

対象となるメソッドは以下のとおりです。

| 型 | メソッド |
|---|---|
| `IUnitOfWork`（およびその実装） | すべてのインスタンスメソッド（`SaveChangesAsync`、`DiscardChanges`、`ExecuteInTransactionAsync`） |
| `DbContext`（およびその派生クラス） | `SaveChanges`、`SaveChangesAsync` |
| `DatabaseFacade`（`DbContext.Database`） | `BeginTransaction(Async)`、`CommitTransaction(Async)`、`RollbackTransaction(Async)`（拡張メソッドのオーバーロードを含む） |
| `IDbContextTransaction` | `Commit(Async)`、`Rollback(Async)` |

この規則は、呼び出し元のアセンブリに `ArchitectureLayerAttribute` が設定されている場合にのみ検証されます。

## 規則の説明

D3Fragments では、変更の保存とトランザクションの制御を Pipeline Behavior（`UnitOfWorkBehavior`・`TransactionBehavior`）が一括して行います。
リクエストハンドラは集約を変更するだけでよく、保存の要否やトランザクションの境界を意識する必要はありません。

リクエストハンドラやリポジトリが独自に保存・トランザクションを操作すると、以下の問題が発生します。

- Handler が業務エラー（例外）で終了した場合でも、それまでの変更が確定してしまう
- `ITransactionalCommand` によるトランザクションの境界や、ドメインイベントの配信タイミング（Commit前・Commit後）が崩れる
- 保存処理が複数の箇所に分散し、変更がどこで確定するのかを追跡できなくなる

`DbContext` の派生クラス（`SaveChangesAsync` のオーバーライドから `base.SaveChangesAsync` を呼び出す場合等）と、`IUnitOfWork` の独自実装は、保存・トランザクションを実装する側であるため対象外です。

## 違反の修正方法

保存・トランザクションの操作を削除してください。

- 変更の保存は `UnitOfWorkBehavior` が Handler の成功後に行います。
- Handler の実行前から明示的なトランザクションが必要な場合（行ロック等）は、リクエストに `ITransactionalCommand` を実装してください。
- 保存のタイミングを独自に制御する必要がある横断的な処理は、`IPipelineBehavior<TRequest, TResponse>` として実装してください。

## 例

```csharp
public sealed class RenameShelfHandler(IShelfRepository shelves, IUnitOfWork unitOfWork) : IRequestHandler<RenameShelf, UuidV7>
{
    public async Task<UuidV7> HandleAsync(RenameShelf command, CancellationToken cancellationToken)
    {
        var shelf = await shelves.FindAsync(command.Id, cancellationToken) ?? throw new EntityNotFoundException(nameof(Shelf));
        shelf.Rename(command.Name);

        // Violates DFR0012
        await unitOfWork.SaveChangesAsync(cancellationToken);
        return shelf.Id;
    }
}
```

```csharp
public sealed class RenameShelfHandler(IShelfRepository shelves) : IRequestHandler<RenameShelf, UuidV7>
{
    public async Task<UuidV7> HandleAsync(RenameShelf command, CancellationToken cancellationToken)
    {
        var shelf = await shelves.FindAsync(command.Id, cancellationToken) ?? throw new EntityNotFoundException(nameof(Shelf));

        // Does not violate DFR0012: UnitOfWorkBehavior saves the changes
        shelf.Rename(command.Name);
        return shelf.Id;
    }
}
```

## 警告を抑制する状況

アプリケーションの起動時に初期データを投入する処理など、リクエストの実行基盤（`IRequestExecutor<TRequest, TResponse>`）を経由しない処理では、警告を抑制してもかまいません。

## 警告を抑制する

単一の違反を抑制するだけの場合は、ソース ファイルにプリプロセッサ ディレクティブを追加して無効にしてから、規則をもう一度有効にします。

```csharp
#pragma warning disable DFR0012
// 規則に違反するコード
#pragma warning restore DFR0012
```

ファイル、フォルダー、プロジェクトの規則を無効にするには、その重要度を `none` に設定し、[設定ファイル](https://learn.microsoft.com/ja-jp/dotnet/fundamentals/code-analysis/configuration-files) で適用します。

```ini
[*.cs]
dotnet_diagnostic.DFR0012.severity = none
```
