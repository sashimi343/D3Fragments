# DFR0016: Request types should implement exactly one of ICommand and IQuery

| Property | Value |
|---|---|
| Rule ID | DFR0016 |
| Title | Request types should implement exactly one of ICommand and IQuery |
| Default severity | Warning |
| Fix is breaking or non-breaking | Non-breaking |
| Code fix | None |

## Cause

A non-abstract class or struct (including records) that implements `IRequest<TResponse>` implements neither or both of `ICommand` and `IQuery`.

Note the following points.

- Implementing `ITransactionalCommand`, which inherits `ICommand`, counts as implementing `ICommand`.
- Abstract types and interfaces are not checked. Implement `ICommand<TResponse>` or `IQuery<TResponse>` in the derived types.

## Rule description

`UnitOfWorkBehavior` treats a request that does not implement `IQuery` as a command and saves changes after the handler runs.
A request that implements `IRequest<TResponse>` directly therefore behaves like a command, and its type does not tell whether it has side effects.
A request that implements both `ICommand` and `IQuery` is treated as a query, and its changes are not saved.

`AddD3FragmentsApplication` also throws `InvalidOperationException` when it registers a handler for such a request. This rule detects the same problem before run time.

## How to fix violations

Implement `ICommand<TResponse>` for a request that changes data, and `IQuery<TResponse>` for a request that does not.

## Example

```csharp
// Violates DFR0016
public sealed record GetShelfQuery(UuidV7 Id) : IRequest<Shelf?>;

// Violates DFR0016
public sealed record AddShelfCommand(string Name) : ICommand<UuidV7>, IQuery<UuidV7>;
```

```csharp
// Does not violate DFR0016
public sealed record GetShelfQuery(UuidV7 Id) : IQuery<Shelf?>;

// Does not violate DFR0016
public sealed record AddShelfCommand(string Name) : ICommand<UuidV7>;
```

## When to suppress warnings

Do not suppress a warning from this rule. A handler for a violating request causes an exception when `AddD3FragmentsApplication` registers it.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable DFR0016
// The code that's violating the rule is on this line.
#pragma warning restore DFR0016
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.cs]
dotnet_diagnostic.DFR0016.severity = none
```
