# DFR0014: Do not disable change tracking in repositories

| Property | Value |
|---|---|
| Rule ID | DFR0014 |
| Title | Do not disable change tracking in repositories |
| Default severity | Warning |
| Fix is breaking or non-breaking | Non-breaking |
| Code fix | None |

## Cause

One of the following EF Core methods is called in a repository implementation class (a class whose module layer is `Infrastructure_RepositoryImplementation`).
For details on module layer names and how module layers are determined, see [Module layers](../guide/01-architecture.md#module-layers).

- `AsNoTracking()`
- `AsNoTrackingWithIdentityResolution()`
- `AsTracking(QueryTrackingBehavior)` (when a constant other than `QueryTrackingBehavior.TrackAll` is passed)

Note the following points.

- Calls in classes other than repositories (such as query services) are not violations.
- Calls inside a shared extension method or a similar helper cannot be detected.
- Changing the default tracking behavior with `DbContextOptionsBuilder.UseQueryTrackingBehavior` is not checked.

This rule is verified only when `ArchitectureLayerAttribute` is set on the calling assembly.

## Rule description

A repository is where aggregates are retrieved in order to change them. In D3Fragments, the Unit of Work saves the changes made to retrieved aggregates through change tracking.
When an aggregate retrieved without change tracking is changed, the changes are lost without any error.

When a read-only query that does not change data (such as a list view) needs performance, move it from the repository to a query service and use `AsNoTracking()` there.
Using `AsNoTracking()` in a query service is the recommended usage.

## How to fix violations

- For a method that retrieves aggregates, remove the call to `AsNoTracking()` and similar methods.
- For a read-only query, move the method to a query service.

For a projection (a query that converts to a type other than the aggregate with `Select`), `AsNoTracking()` has no effect, so remove the call.

## Example

```csharp
public sealed class ShelfRepository(AppDbContext dbContext) : RepositoryBase<AppDbContext, Shelf>(dbContext), IShelfRepository
{
    // Violates DFR0014
    public Task<Shelf?> FindByNameAsync(ShelfName name, CancellationToken cancellationToken)
        => Set.AsNoTracking().SingleOrDefaultAsync(x => x.Name == name, cancellationToken);
}
```

```csharp
public sealed class ShelfRepository(AppDbContext dbContext) : RepositoryBase<AppDbContext, Shelf>(dbContext), IShelfRepository
{
    // Does not violate DFR0014
    public Task<Shelf?> FindByNameAsync(ShelfName name, CancellationToken cancellationToken)
        => Set.SingleOrDefaultAsync(x => x.Name == name, cancellationToken);
}

public sealed class ShelfQueryService(AppDbContext dbContext) : IShelfQueryService
{
    // Does not violate DFR0014: read-only queries belong to a query service
    public Task<Pager<ShelfSummary>> ListAsync(int pageNo, int pageSize, CancellationToken cancellationToken)
        => dbContext.Shelves.AsNoTracking()
            .OrderBy(x => x.Id)
            .Select(x => new ShelfSummary(x.Id, x.Name.Value))
            .ToPagedListAsync(pageNo, pageSize, cancellationToken);
}
```

## When to suppress warnings

In general, do not suppress a warning from this rule.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable DFR0014
// The code that's violating the rule is on this line.
#pragma warning restore DFR0014
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.cs]
dotnet_diagnostic.DFR0014.severity = none
```
