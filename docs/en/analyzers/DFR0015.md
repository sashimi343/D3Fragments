# DFR0015: Override FindAsync in repositories of aggregates that contain child entities

| Property | Value |
|---|---|
| Rule ID | DFR0015 |
| Title | Override FindAsync in repositories of aggregates that contain child entities |
| Default severity | Warning |
| Fix is breaking or non-breaking | Non-breaking |
| Code fix | None |

## Cause

A non-abstract class that inherits `RepositoryBase<TContext, TAggregate, TId>` (or `RepositoryBase<TContext, TAggregate>`) does not override `FindAsync`, and the aggregate root `TAggregate` has a property that references child entities (types that inherit `Entity<TId>` but not `AggregateRoot<TId>`).

Note the following points.

- Property types are inspected recursively, including array element types and generic type arguments (such as `IReadOnlyList<T>`).
- Properties that reference other aggregate roots are not checked.
- Overriding `FindAsync` in an intermediate base class between the repository and `RepositoryBase` is not a violation.
- Whether the overriding `FindAsync` actually includes the child entities is not verified.
- Custom retrieval methods other than `FindAsync` are not checked.

## Rule description

The default `FindAsync` of `RepositoryBase` loads only the aggregate root with `DbSet.FindAsync` and does not load its child entities.
An aggregate is a unit of consistency. Operating on an aggregate whose child entities are not loaded can lead to wrong invariant checks or lost changes to the child entities.

## How to fix violations

Override `FindAsync` and load the child entities with `Include`.

## Example

```csharp
public sealed class Shelf : AggregateRoot
{
    private readonly List<ShelfItem> _items = [];

    public IReadOnlyList<ShelfItem> Items => _items;
}

// Violates DFR0015
public sealed class ShelfRepository(AppDbContext dbContext) : RepositoryBase<AppDbContext, Shelf>(dbContext), IShelfRepository;
```

```csharp
// Does not violate DFR0015
public sealed class ShelfRepository(AppDbContext dbContext) : RepositoryBase<AppDbContext, Shelf>(dbContext), IShelfRepository
{
    public override Task<Shelf?> FindAsync(UuidV7 id, CancellationToken cancellationToken)
        => Set.Include(x => x.Items).SingleOrDefaultAsync(x => x.Id == id, cancellationToken);
}
```

## When to suppress warnings

It is safe to suppress a warning from this rule when the default `FindAsync` loads the child entities, for example when `AutoInclude()` is configured for the navigation to the child entities in `OnModelCreating`.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable DFR0015
// The code that's violating the rule is on this line.
#pragma warning restore DFR0015
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.cs]
dotnet_diagnostic.DFR0015.severity = none
```
