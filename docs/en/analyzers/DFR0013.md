# DFR0013: Do not call Update or Attach for entities

| Property | Value |
|---|---|
| Rule ID | DFR0013 |
| Title | Do not call Update or Attach for entities |
| Default severity | Warning |
| Fix is breaking or non-breaking | Non-breaking |
| Code fix | None |

## Cause

One of the following EF Core methods is called for a class that directly or indirectly inherits the `D3Fragments.EntityBase<TId>` class (an entity).

| Type | Methods |
|---|---|
| `DbContext` (and its derived classes) | `Update`, `UpdateRange`, `Attach`, `AttachRange` |
| `DbSet<TEntity>` | `Update`, `UpdateRange`, `Attach`, `AttachRange` |

Note the following points.

- The target type is `TEntity` for `DbSet<TEntity>`, the type argument for the generic methods of `DbContext`, and the static type of the argument (the element type for an array or a collection) for the non-generic methods (`object` parameters). When the static type is `object`, the call cannot be detected.
- Calls for types other than entities (such as tables whose keys are generated by the database) are not violations.
- `ExecuteUpdate` and `ExecuteDelete` are not checked.
- Methods with the same name defined on an entity (for example, `order.Update(...)`) are not checked.

This rule is verified only when `ArchitectureLayerAttribute` is set on the calling assembly.

## Rule description

Entities in D3Fragments generate their ID (UUIDv7) in the constructor, so their key is already set when they are created.
Because EF Core's `Update` and `Attach` treat an entity whose key is set as an existing row, the following problems occur.

- A newly added child entity is updated instead of inserted, and `DbUpdateConcurrencyException` is thrown (`Update`).
- A newly added child entity is treated as `Unchanged` and is not inserted (`Attach`).

In D3Fragments, aggregates are retrieved with change tracking enabled, and the Unit of Work saves the changes made to retrieved aggregates. Therefore, there is no need to call `Update` or `Attach`.

## How to fix violations

Remove the call to `Update` or `Attach`.

- To change an existing aggregate, call the methods of the (tracked) aggregate retrieved through the repository.
- To add a new aggregate, use `Add` of the repository.

## Example

```csharp
public sealed class ShelfRepository(AppDbContext dbContext) : RepositoryBase<AppDbContext, Shelf>(dbContext), IShelfRepository
{
    // Violates DFR0013
    public void Save(Shelf shelf) => DbContext.Update(shelf);
}
```

```csharp
public sealed class RenameShelfHandler(IShelfRepository shelves) : IRequestHandler<RenameShelf, UuidV7>
{
    public async Task<UuidV7> HandleAsync(RenameShelf command, CancellationToken cancellationToken)
    {
        var shelf = await shelves.FindAsync(command.Id, cancellationToken) ?? throw new EntityNotFoundException(nameof(Shelf));

        // Does not violate DFR0013: the tracked aggregate is saved by the Unit of Work
        shelf.Rename(command.Name);
        return shelf.Id;
    }
}
```

## When to suppress warnings

In general, do not suppress a warning from this rule.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable DFR0013
// The code that's violating the rule is on this line.
#pragma warning restore DFR0013
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.cs]
dotnet_diagnostic.DFR0013.severity = none
```
