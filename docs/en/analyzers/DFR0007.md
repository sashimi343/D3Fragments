# DFR0007: Specify the declaring type itself for the self-referencing type parameter TSelf

| Property | Value |
|---|---|
| Rule ID | DFR0007 |
| Title | Specify the declaring type itself for the self-referencing type parameter TSelf |
| Default severity | Warning |
| Fix is breaking or non-breaking | Breaking |
| Code fix | No |

## Cause

One of the following types is directly specified in the base type list of a class, struct, or record, and a type other than the declaring type itself is specified for its type argument `TSelf`.

- `D3Fragments.TypeSafeEnum<TSelf, TKey>` (base class)
- `D3Fragments.ValueObjectBase<TSelf, TPrimitive>` (base class)
- `D3Fragments.IValueObject<TSelf, TPrimitive>` (implemented interface)

If `TSelf` is a type parameter (such as in a generic intermediate base class), it is not a violation.
If the declaring type is a generic type, the type constructed with its own type parameters (for example, `class Foo<T> : TypeSafeEnum<Foo<T>, int>`) is regarded as the declaring type itself.

This rule is verified regardless of the architecture layer setting of the assembly (`ArchitectureLayerAttribute`).

## Rule description

`TSelf` is a type parameter that represents the derived class itself. The base classes are implemented on the assumption that `TSelf` is the derived class itself.
For example, `TypeSafeEnum<TSelf, TKey>` casts itself to `TSelf` in its constructor, so specifying another type for `TSelf` causes an `InvalidCastException` when a value is defined.
Type parameter constraints alone cannot detect this mistake at compile time, so this rule detects it.

## How to fix violations

Specify the declaring type itself for `TSelf`.

## Example

```csharp
public class UserType : TypeSafeEnum<UserType, int> { ... }

// Violates DFR0007
public class AdminType : TypeSafeEnum<UserType, int> { ... }
```

```csharp
// Does not violate DFR0007
public class AdminType : TypeSafeEnum<AdminType, int> { ... }
```

## When to suppress warnings

Do not suppress a warning from this rule.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable DFR0007
// The code that's violating the rule is on this line.
#pragma warning restore DFR0007
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.cs]
dotnet_diagnostic.DFR0007.severity = none
```
