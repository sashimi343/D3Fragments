# DFR0019: Query handlers should not execute commands

| Property | Value |
|---|---|
| Rule ID | DFR0019 |
| Title | Query handlers should not execute commands |
| Default severity | Warning |
| Fix is breaking or non-breaking | Non-breaking |
| Code fix | None |

## Cause

A constructor parameter of a query handler (an implementation of `IRequestHandler<TRequest, TResponse>` whose request implements `IQuery`) is an `IRequestExecutor<TRequest, TResponse>` or `IIsolatedRequestExecutor<TRequest, TResponse>` that executes a command.

Note the following:

- The parameters of all instance constructors, including primary constructors, are checked.
- All classes and interfaces that implement `IRequestExecutor<TRequest, TResponse>` are reported.
- Executors of a query are not reported.
- Executors whose request type is a type parameter are not reported, because whether the request is a command or a query cannot be determined.

This rule is checked only when `ArchitectureLayerAttribute` is set on the assembly.

## Rule description

A query is a request that reads data without changing state.
When a query handler executes a command, processing that should only read data updates the database.
To the caller, the state appears to change just because it executed a read.

## How to fix violations

Do not execute a command from a query handler. Rewrite it in one of the following ways:

- For a state change needed before the read (such as deleting expired data), consider handling it in the read conditions instead of in the query. For example, instead of deleting expired data, exclude it from what the query reads, and delete it in a batch process or similar
- If the state must change, make the request a command

## Example

```csharp
public sealed class GetAvailableSeatsQueryHandler(IIsolatedRequestExecutor<DeleteExpiredReservationsCommand, int> deleteExpired)
    : IRequestHandler<GetAvailableSeatsQuery, IReadOnlyList<SeatDto>>
{
    // Violates DFR0019
}
```

```csharp
public sealed class GetAvailableSeatsQueryHandler(ISeatQueries seats, TimeProvider timeProvider)
    : IRequestHandler<GetAvailableSeatsQuery, IReadOnlyList<SeatDto>>
{
    // Does not violate DFR0019: excludes expired reservations in the availability condition
    public Task<IReadOnlyList<SeatDto>> HandleAsync(GetAvailableSeatsQuery request, CancellationToken cancellationToken)
        => seats.FindAvailableAsync(timeProvider.GetUtcNow(), cancellationToken);
}
```

## When to suppress warnings

In general, do not suppress a warning from this rule.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable DFR0019
// The code that's violating the rule is on this line.
#pragma warning restore DFR0019
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.cs]
dotnet_diagnostic.DFR0019.severity = none
```
