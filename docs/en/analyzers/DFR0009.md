# DFR0009: Entities should not expose mutable collections

| Property | Value |
|---|---|
| Rule ID | DFR0009 |
| Title | Entities should not expose mutable collections |
| Default severity | Warning |
| Fix is breaking or non-breaking | Breaking |
| Code fix | No |

## Cause

A class that directly or indirectly inherits the `D3Fragments.EntityBase<TId>` class declares a property or field whose type is a mutable collection with the following accessibility.

- Property: the accessibility of the `get` accessor is `public`, `internal`, or `protected internal`
- Field: the accessibility is `public`, `internal`, or `protected internal` (regardless of whether it is `readonly`)

A mutable collection is a type that meets one of the following.

- An array
- `System.Collections.Generic.ICollection<T>` or `System.Collections.Generic.IDictionary<TKey, TValue>`, or a type that implements either of them (`List<T>`, `IList<T>`, `HashSet<T>`, `Dictionary<TKey, TValue>`, and so on)

However, the following types are not regarded as mutable collections.

- `System.Collections.ObjectModel.ReadOnlyCollection<T>`, `ReadOnlyDictionary<TKey, TValue>`, `ReadOnlySet<T>`, and `ReadOnlyObservableCollection<T>`
- Types in the `System.Collections.Immutable` namespace

The accessibility of the setter does not matter. The accessibility of the class itself, explicit interface implementations, and where violations are reported are handled in the same way as [DFR0003](DFR0003.md).

This rule cannot detect a property exposed as a read-only interface type such as `IReadOnlyList<T>` that returns a `List<T>` instance internally and is cast and modified by the caller.

This rule is verified regardless of the architecture layer setting of the assembly (`ArchitectureLayerAttribute`).

## Rule description

The state of an entity should be changed through operations (methods).
If a mutable collection is exposed, callers can change the state of the entity with collection operations such as `Add` and `Remove` even if the setter is not public, which causes the same problem as [DFR0003](DFR0003.md).

## How to fix violations

Hold the collection in a `private` field and expose it as a read-only interface type such as `IReadOnlyList<T>` or `IReadOnlyCollection<T>`.
Implement changes to the collection as operations (methods) of the entity.

## Example

```csharp
public class Bookshelf : AggregateRoot<UuidV7>
{
    // Violates DFR0009
    public List<Book> Books { get; private set; } = [];
}
```

```csharp
public class Bookshelf : AggregateRoot<UuidV7>
{
    private readonly List<Book> _books = [];

    // Does not violate DFR0009
    public IReadOnlyList<Book> Books => _books;

    public void AddBook(Book book)
    {
        ...
        _books.Add(book);
    }
}
```

## When to suppress warnings

In general, do not suppress a warning from this rule.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable DFR0009
// The code that's violating the rule is on this line.
#pragma warning restore DFR0009
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.cs]
dotnet_diagnostic.DFR0009.severity = none
```
