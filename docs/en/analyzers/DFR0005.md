# DFR0005: Do not define repository methods that update part of an aggregate

| Property | Value |
|---|---|
| Rule ID | DFR0005 |
| Title | Do not define repository methods that update part of an aggregate |
| Default severity | Warning |
| Fix is breaking or non-breaking | Breaking |
| Code fix | No |

## Cause

An interface that directly or indirectly inherits the `D3Fragments.IRepository<TAggregate, TId>` interface (including inheritance through `IRepository<TAggregate>`) declares a method whose parameter type contains an entity (a class that directly or indirectly inherits `EntityBase<TId>`) other than `TAggregate`.

The parameter types are inspected in the same way as the return type in [DFR0004](DFR0004.md), and the inspected methods are also the same (including `ref`, `out`, `in`, and `params` parameters). A violation is reported for each such parameter.

Not only methods for updates but also methods that receive a part of an aggregate as a search condition are violations. Pass the ID of the entity as a search condition instead of the entity.

This rule is verified regardless of the architecture layer setting of the assembly (`ArchitectureLayerAttribute`).

## Rule description

Entities should be updated through repositories in units of aggregates.
If some entities of an aggregate can be updated on their own, those entities are changed without going through the methods of the aggregate root.
As a result, changes that violate the rules (invariants) enforced by the aggregate root may be saved.

## How to fix violations

Change the method to receive the aggregate root itself as a parameter instead of a part of the aggregate.
If the parameter is used as a search condition, change it to receive the ID instead of the entity.

## Example

```csharp
public interface IBookshelfRepository : IRepository<Bookshelf, UuidV7>
{
    // Violates DFR0005
    void UpdateBook(Book book);

    // Violates DFR0005
    Task<Bookshelf?> FindByBookAsync(Book book, CancellationToken cancellationToken);
}
```

```csharp
public interface IBookshelfRepository : IRepository<Bookshelf, UuidV7>
{
    // Does not violate DFR0005
    Task<Bookshelf?> FindByBookIdAsync(UuidV7 bookId, CancellationToken cancellationToken);
}
```

## When to suppress warnings

In general, do not suppress a warning from this rule.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable DFR0005
// The code that's violating the rule is on this line.
#pragma warning restore DFR0005
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.cs]
dotnet_diagnostic.DFR0005.severity = none
```
