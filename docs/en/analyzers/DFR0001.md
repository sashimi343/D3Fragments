# DFR0001: Architecture reference violation (project reference)

| Property | Value |
|---|---|
| Rule ID | DFR0001 |
| Title | Architecture reference violation (project reference) |
| Default severity | Warning |
| Fix is breaking or non-breaking | Non-breaking |
| Code fix | No |

## Cause

A dependency between projects is inappropriate. An assembly with a higher level of abstraction should not depend on an assembly with a lower level of abstraction.
The rules that allow or forbid dependencies between layers are as follows.

| from / to      | Presentation | Application | Domain | Infrastructure |
| :------------- | :----------: | :---------: | :----: | :------------: |
| Presentation   | ○            | ○           | ○      | *1             |
| Application    | ×            | ○           | ○      | ×              |
| Domain         | ×            | ×           | ○      | ×              |
| Infrastructure | ×            | ○           | ○      | ○              |

*1: This reference is intended for registrations in the DI container. Using the infrastructure layer from anything other than DI container registrations (such as controllers) is reported by [DFR0002](DFR0002.md).

If the assemblies referenced at compile time (by project references or package references, including transitive references) include an assembly with a forbidden dependency, this violation is reported in the referencing (from) project.
The violation is reported as a project-level diagnostic that has no location in the source code.

This rule is verified only when `ArchitectureLayerAttribute` is set on both the referencing and the referenced assemblies. References from or to an assembly without `ArchitectureLayerAttribute` are always allowed.

If the referencing or the referenced assembly has multiple architecture layers, the reference is allowed when a dependency from any architecture layer of the referencing assembly to any architecture layer of the referenced assembly is allowed (○).
Therefore, the verification between architecture layers by this rule is limited for assemblies with multiple architecture layers. In addition, dependencies between architecture layers within the same assembly are not verified by this rule. These are partially verified per module layer by [DFR0002](DFR0002.md).

## Rule description

D3Fragments assumes an architecture based on Clean Architecture.
In this architecture, dependencies point in one direction only: from the outer layers toward the inner layer (the domain layer).
Keeping this direction means that the code in the domain and application layers does not depend on EF Core or ASP.NET Core.
You can change how the database is accessed or how the UI is implemented without rewriting these layers.

## How to fix violations

To fix a violation of this rule, remove the forbidden project references and package references from the csproj.
If the violation is reported because of a transitive reference, review the direct reference that brings in that reference.

## Example

```csharp
// AssemblyInfo.cs of the MyApp.Domain project
[assembly: ArchitectureLayer(ArchitectureLayerType.Domain)]

// AssemblyInfo.cs of the MyApp.Application project
[assembly: ArchitectureLayer(ArchitectureLayerType.Application)]
```

```xml
<!-- MyApp.Domain.csproj -->
<ItemGroup>
  <!-- Violates DFR0001: references from Domain to Application are forbidden -->
  <ProjectReference Include="..\MyApp.Application\MyApp.Application.csproj" />
</ItemGroup>
```

## When to suppress warnings

In general, do not suppress a warning from this rule.

## Suppress a warning

A violation of this rule has no location in the source code, so it cannot be suppressed by adding preprocessor directives to a source file or by file-level settings in `.editorconfig`.
To disable the rule for a project, add the rule ID to `NoWarn` in the csproj.

```xml
<PropertyGroup>
  <NoWarn>$(NoWarn);DFR0001</NoWarn>
</PropertyGroup>
```

Alternatively, set its severity to `none` in a [global AnalyzerConfig file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files#global-analyzerconfig).

```ini
is_global = true
dotnet_diagnostic.DFR0001.severity = none
```
