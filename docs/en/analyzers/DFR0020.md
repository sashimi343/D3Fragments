# DFR0020: Execute immediate operations in repositories through ExecuteImmediateAsync

| Property | Value |
|---|---|
| Rule ID | DFR0020 |
| Title | Execute immediate operations in repositories through ExecuteImmediateAsync |
| Default severity | Warning |
| Fix is breaking or non-breaking | Non-breaking |
| Code fix | None |

## Cause

In a repository implementation class (a class whose module layer is `Infrastructure_RepositoryImplementation`), one of the following EF Core methods, which run against the database immediately, is called outside the lambda passed to `RepositoryBase.ExecuteImmediateAsync`.
For details on module layer names and how module layers are determined, see [Module layers](../guide/01-architecture.md#module-layers).

- `ExecuteUpdate` and `ExecuteUpdateAsync`
- `ExecuteDelete` and `ExecuteDeleteAsync`
- `Database.ExecuteSql`, `ExecuteSqlRaw`, `ExecuteSqlInterpolated`, and their asynchronous versions

Note the following points.

- Calls in classes other than repositories (such as query services) are not violations.
- Calls inside the lambda passed to `ExecuteImmediateAsync` (including lambdas nested in it) are not violations. Calls inside another method called from the lambda are reported as violations.
- Calls inside a shared extension method or a similar helper cannot be detected.

This rule is verified only when `ArchitectureLayerAttribute` is set on the calling assembly.

## Rule description

In D3Fragments, `UnitOfWorkBehavior` saves the tracked changes after the handler finishes.
An immediate operation, on the other hand, runs in the middle of the handler, at the point where it is called. This causes the following problems.

- The order is reversed: aggregates added or changed in the same command are not saved yet when the immediate operation runs. A process that saves changes and then runs bulk SQL that uses them does not work correctly.
- Outside a transaction, it is committed at once: in a command that is not an `ITransactionalCommand`, the immediate operation is committed immediately by auto-commit. It is not undone even if the handler throws an exception afterward, which breaks the assumption that nothing is saved when a command fails.

`ExecuteImmediateAsync` checks that a transaction has been started (it throws `InvalidOperationException` outside a transaction), saves the pending changes, and then runs the operation.
The saved changes are not committed, and they are rolled back with the transaction if the command fails.

## How to fix violations

Call the immediate operation inside the lambda passed to `ExecuteImmediateAsync`, and make the commands that use it implement `ITransactionalCommand`.

## Example

```csharp
public sealed class ReservationRepository(LibraryDbContext dbContext)
    : RepositoryBase<LibraryDbContext, Reservation>(dbContext), IReservationRepository
{
    // Violates DFR0020
    public Task<int> DeleteExpiredAsync(DateOnly today, CancellationToken cancellationToken) =>
        Set.Where(x => x.HoldUntil < today).ExecuteDeleteAsync(cancellationToken);
}
```

```csharp
public sealed class ReservationRepository(LibraryDbContext dbContext)
    : RepositoryBase<LibraryDbContext, Reservation>(dbContext), IReservationRepository
{
    // Does not violate DFR0020
    public Task<int> DeleteExpiredAsync(DateOnly today, CancellationToken cancellationToken) =>
        ExecuteImmediateAsync(ct => Set.Where(x => x.HoldUntil < today).ExecuteDeleteAsync(ct), cancellationToken);
}
```

## When to suppress warnings

In general, do not suppress a warning from this rule.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable DFR0020
// The code that's violating the rule is on this line.
#pragma warning restore DFR0020
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.cs]
dotnet_diagnostic.DFR0020.severity = none
```
