# DFR0006: Do not expose constructors of TypeSafeEnum types outside the class

| Property | Value |
|---|---|
| Rule ID | DFR0006 |
| Title | Do not expose constructors of TypeSafeEnum types outside the class |
| Default severity | Warning |
| Fix is breaking or non-breaking | Breaking |
| Code fix | Yes (constructors other than primary constructors only) |

## Cause

In this rule, a class that directly specifies `D3Fragments.TypeSafeEnum<TSelf, TKey>` as its base class is called a "TypeSafeEnum type". However, a class whose `TSelf` is a type parameter (a generic intermediate base class) is not a TypeSafeEnum type.

A violation occurs in one of the following cases.

- The accessibility of an instance constructor of a TypeSafeEnum type is not `private` (static constructors are excluded)
- A TypeSafeEnum type has a primary constructor (because a primary constructor is always `public`)
- A class that directly or indirectly inherits a TypeSafeEnum type is not declared as a `private` nested class of that TypeSafeEnum type

This rule is verified regardless of the architecture layer setting of the assembly (`ArchitectureLayerAttribute`).

## Rule description

Exposing a constructor outside the class allows unintended values to be created, so avoid exposing constructors.

To change the behavior for each value, make the TypeSafeEnum type an abstract class and define each value with a `private` nested class. If a nested class is declared with an accessibility other than `private`, values can be created from outside through the constructor of the nested class, so it is a violation.

## How to fix violations

Change the accessibility of the constructor to `private`.
If you use a primary constructor, rewrite it as a regular constructor and make it `private`.
If you define values with nested classes, make the nested classes `private`.

The code fix changes the accessibility of constructors other than primary constructors to `private`.

## Example

```csharp
public class UserType : TypeSafeEnum<UserType, int>
{
    public static readonly UserType Normal = new(0, "Normal user");
    public static readonly UserType Admin = new(1, "Administrator");

    // Violates DFR0006
    protected UserType(int key, string name) : base(key, name) {}
}

// Violates DFR0006
public class Color(string key) : TypeSafeEnum<Color, string>(key)
{
    public static readonly Color Red = new("red");
}
```

```csharp
public class UserType : TypeSafeEnum<UserType, int>
{
    public static readonly UserType Normal = new(0, "Normal user");
    public static readonly UserType Admin = new(1, "Administrator");

    // Does not violate DFR0006
    private UserType(int key, string name) : base(key, name) {}
}

public abstract class Shape : TypeSafeEnum<Shape, string>
{
    public static readonly Shape Circle = new CircleShape();

    private Shape(string key) : base(key) {}

    public abstract double Area(double size);

    // Does not violate DFR0006
    private sealed class CircleShape() : Shape("circle")
    {
        public override double Area(double size) => Math.PI * size * size;
    }
}
```

## When to suppress warnings

In general, do not suppress a warning from this rule.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable DFR0006
// The code that's violating the rule is on this line.
#pragma warning restore DFR0006
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.cs]
dotnet_diagnostic.DFR0006.severity = none
```
