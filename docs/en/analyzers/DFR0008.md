# DFR0008: Define TypeSafeEnum values as static readonly fields

| Property | Value |
|---|---|
| Rule ID | DFR0008 |
| Title | Define TypeSafeEnum values as static readonly fields |
| Default severity | Warning |
| Fix is breaking or non-breaking | Breaking |
| Code fix | No |

## Cause

In this rule, a class that directly specifies `D3Fragments.TypeSafeEnum<TSelf, TKey>` as its base class is called a "TypeSafeEnum type". However, a class whose `TSelf` is a type parameter (a generic intermediate base class) is not a TypeSafeEnum type.

A violation occurs in one of the following cases within the declaration of a TypeSafeEnum type (including nested classes).

- An instance of the TypeSafeEnum type (or its derived class) is created (with a `new` expression, including target-typed `new`) somewhere other than the initializer of a `static readonly` field of the TypeSafeEnum type
  - Examples: the expression body of a static property (`static X => new(...)`), the initializer of an auto-implemented property (`static X { get; } = new(...)`), and inside a method
- A static field whose type is the TypeSafeEnum type (or its derived class) is not `readonly`

This rule is verified regardless of the architecture layer setting of the assembly (`ArchitectureLayerAttribute`).

## Rule description

The key and name of a TypeSafeEnum value are registered when the instance is created, and each value is assumed to exist as a single instance.

- If a value is created in the expression body of a static property or similar, a new instance is created on every access, and an `ArgumentException` occurs due to a duplicate key.
- If a value is defined by a static field that is not `readonly`, a defined value can be replaced with another instance.

## How to fix violations

Define values as `static readonly` fields of the TypeSafeEnum type.

## Example

```csharp
public class UserType : TypeSafeEnum<UserType, int>
{
    // Violates DFR0008
    public static UserType Normal => new(0, "Normal user");

    // Violates DFR0008
    public static UserType Admin = new(1, "Administrator");

    private UserType(int key, string name) : base(key, name) {}
}
```

```csharp
public class UserType : TypeSafeEnum<UserType, int>
{
    // Does not violate DFR0008
    public static readonly UserType Normal = new(0, "Normal user");
    public static readonly UserType Admin = new(1, "Administrator");

    private UserType(int key, string name) : base(key, name) {}
}
```

## When to suppress warnings

Do not suppress a warning from this rule.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable DFR0008
// The code that's violating the rule is on this line.
#pragma warning restore DFR0008
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.cs]
dotnet_diagnostic.DFR0008.severity = none
```
