# DFR0004: Do not define repository methods that retrieve part of an aggregate

| Property | Value |
|---|---|
| Rule ID | DFR0004 |
| Title | Do not define repository methods that retrieve part of an aggregate |
| Default severity | Warning |
| Fix is breaking or non-breaking | Breaking |
| Code fix | No |

## Cause

An interface that directly or indirectly inherits the `D3Fragments.IRepository<TAggregate, TId>` interface (including inheritance through `IRepository<TAggregate>`) declares a method whose return type contains an entity (a class that directly or indirectly inherits `EntityBase<TId>`) other than `TAggregate`.

The return type is inspected recursively as follows, and a violation occurs if any of them contains such a type.

- The return type itself
- The element type of an array
- The type arguments of a generic type (`Task<T>`, `ValueTask<T>`, `IAsyncEnumerable<T>`, `IReadOnlyList<T>`, `Dictionary<TKey, TValue>`, `Result<T>`, tuples, and so on, including nested type arguments)

Note the following.

- Classes that directly or indirectly inherit `TAggregate` are not violations.
- Aggregate roots other than `TAggregate` (other aggregates) are also violations. Retrieve other aggregates from the repositories of those aggregates.
- Only the methods declared in the interface are inspected (methods of a base interface are inspected in that base interface).
- Methods added in repository implementation classes are not inspected.
- Generic interfaces whose aggregate root is a type parameter (for example, `IReadRepository<T> : IRepository<T>`) are not inspected because the aggregate root is not determined.

This rule is verified regardless of the architecture layer setting of the assembly (`ArchitectureLayerAttribute`).

## Rule description

Entities should be retrieved through repositories in units of aggregates.
If a method that returns only some entities of an aggregate is implemented, the consistency of the aggregate can be broken.

## How to fix violations

Change the method to return the aggregate root itself instead of a part of the aggregate.
If only a part of the data of an aggregate is required for reading, such as for display, provide a separate query that returns a read DTO instead of entities.

## Example

```csharp
public class Bookshelf : AggregateRoot<UuidV7>
{
    public IReadOnlyList<Book> Books => _books;
    ...
}

public class Book : Entity<UuidV7> { ... }

public interface IBookshelfRepository : IRepository<Bookshelf, UuidV7>
{
    // Violates DFR0004
    Task<IReadOnlyList<Book>> FindBooksAsync(UuidV7 bookshelfId, CancellationToken cancellationToken);
}
```

```csharp
public interface IBookshelfRepository : IRepository<Bookshelf, UuidV7>
{
    // Does not violate DFR0004
    Task<IReadOnlyList<Bookshelf>> FindByOwnerAsync(UuidV7 ownerId, CancellationToken cancellationToken);
}
```

## When to suppress warnings

In general, do not suppress a warning from this rule.

## Suppress a warning

If you just want to suppress a single violation, add preprocessor directives to your source file to disable and then re-enable the rule.

```csharp
#pragma warning disable DFR0004
// The code that's violating the rule is on this line.
#pragma warning restore DFR0004
```

To disable the rule for a file, folder, or project, set its severity to `none` in the [configuration file](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-files).

```ini
[*.cs]
dotnet_diagnostic.DFR0004.severity = none
```
