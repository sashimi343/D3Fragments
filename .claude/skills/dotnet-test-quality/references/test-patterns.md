# 穴の種類ごとのテストパターン

どのパターンも、固定してよいのはドキュメント（XML ドキュメントを含む）か既存のテストで裏付けがある挙動だけ。

## 境界値

- 最小・最大・範囲・長さのルールは「ちょうど」と「1 つ超え」を両方テストする（`<` と `<=` の取り違えを検出する）。
- 0、負の値、空文字、空のコレクション、最小値と最大値が同じ範囲も見る。
- 日時は境界ちょうど（「今」と等しい値）と ±1 tick / 1 秒。
- `[Theory]` + `[InlineData]` で表にすると、境界の抜けが見えやすい。

## 成功・失敗の両方の経路と、すべてのオーバーロード

- `Result` 型や `TryXxx` は、成功と失敗の両方を、オーバーロードごとにテストする。
- 例外を投げるオーバーロード（エラーコード指定・例外ファクトリ指定など）は、成功時に自身や値を返すことも確認する。
- 失敗時に「値を生成する関数が呼ばれない」ことは、呼ばれたら例外を投げるラムダで確かめる。

## テスト支援コード（アサーションヘルパー・テスト基盤）

- 「失敗すべきときに失敗する」ことをテストする（`Assert.ThrowsAny<XunitException>(...)`）。成功ケースだけでは中身を消しても通る。
- テスト基盤の後始末（トランザクション、DbContext、コンテナの破棄）を確かめる。`DisposeAsync` を 2 回呼んでも安全かも見る。
- 大きなインターフェースの外部依存（例: Testcontainers のコンテナ）は、`System.Reflection.DispatchProxy` で
  呼び出しを記録する偽物を作ると、Docker なしで流れ（起動・初期化・破棄の順序、遅延生成）を検証できる。

## 等価性

- 自分自身との比較は `a.Equals(a)` を明示的に呼ぶ。**xUnit の `Assert.Equal(a, a)` は参照が同じだと `Equals` を呼ばない**。
- 別インスタンスで同じ値、異なる値、型が異なる（同じ ID でも型違いは不等）、`Equals(object)` に別の型。
- `==` / `!=` の左右それぞれに null、null 同士。`GetHashCode` の一致。

## null ガード・引数検証

- `Assert.Throws<ArgumentNullException>`（`ParamName` まで見ると強い）。
- ガードがないと `NullReferenceException` になる、遅延評価で例外が列挙時まで遅れる場合は、テストで区別できる。
  直後の処理が同じ例外を投げる場合は等価ミュータント（mutant-triage.md）なので無理にテストしない。

## コレクション・クエリ

- **件数だけでなく中身を検証する。** ページングのテストが件数しか見ていないと、`Skip` の計算を壊しても通る。
- 先頭・中間・末尾のページ、最終ページを超えたページ、0 件。

## DI 登録・設定

- 登録されたサービスや `IOptions<T>` を実際に解決して、設定内容（登録されたコンバータなど）を確かめる。
- 利用者が渡したコールバック（`configure` など）が呼ばれたことを確かめる。
- アセンブリ走査による自動登録は、走査されていれば検出される状態（例: 重複登録の例外）を使って、走査の有無を確かめられる。
- モデルや設定の構築を伴う検証は、テスト用の設定が本番の前提（必要な型の登録など）を満たしているかに注意する。

## ログ

- 記録用の `ILoggerProvider` を `AddLogging(b => b.AddProvider(...))` で登録し、カテゴリ・レベル・メッセージを確かめる。

## 時刻・カルチャ

- 時刻は固定の `TimeProvider`（`LocalTimeZone` も指定できるもの）を使い、`Thread.Sleep` / `Task.Delay` に頼らない。
  ローカル日付で判定する処理は、UTC と日付がずれるタイムゾーンでテストする。
- ローカライズされたメッセージは原則検証しない。`ErrorType`・`Target`・`ParamName` などで検証する。
  検証が必要なら `CultureInfo.CurrentUICulture` を try/finally で切り替える。

## static な登録（型安全な列挙型など）

- 重複定義は型の初期化時に例外になる。`Assert.Throws<TypeInitializationException>` の `InnerException` と `ParamName` を見る。
- 定義用の型はテストごとに別の型にする（一度初期化に失敗した型はプロセス内で使えない）。

## EF Core

- `SaveChanges` と `SaveChangesAsync` の両方をオーバーライドしているなら、両方テストする。
- 外部キーが必須の関連と任意の関連は、子をコレクションから外したときの挙動が違う（必須は削除、任意は null になる）。
  両方のモデルを用意する。
- 任意の拡張設定（`UseXxx`）を使わない構成でも動くかを見る。

## Roslyn のコード修正

- 修飾子付きのアクセサやメンバーが別の行にある場合のインデント（トリビア）の保持。
- 属性付きのアクセサ、アクセス修飾子が複数（`protected internal`）、アクセス修飾子以外の修飾子（`unsafe` など）の保持と並び順。
- `unsafe` を含むテストコードは、`SolutionTransforms` で `CSharpCompilationOptions.WithAllowUnsafe(true)` を設定する。

## 追加しないもの

- アサーションがない、または変異を入れても結果が変わらないテスト。
- ドキュメントにない実装の詳細（「後から呼んだ設定が勝つ」など）を仕様として固定するテスト。
- 到達しないコードを無理に通すための、本番では起きない状態を作るテスト。
