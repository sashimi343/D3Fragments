# 生存ミュータントの分類

生存（Survived / NoCoverage）を次の 4 つに分ける。分類の根拠はソースを読んで確かめ、推測で決めない。

| 分類 | 意味 | 対応 |
|---|---|---|
| 本物の穴 | テストを足せば kill できる | テストを追加する |
| 等価ミュータント | 変異しても観測できる挙動が変わらない | 除外し、理由を記録する |
| 未計測（誤判定） | ツールが変異を有効化できず、実際には kill される | 手で変異を入れて確かめ、除外する |
| 到達しないコード | その分岐に入る入力が存在しない | 除外し、理由を記録する。削るかは src の判断としてユーザーに委ねる |

## 等価ミュータントの既知パターン

- `ConfigureAwait(false)` → `true`: テストでは同期コンテキストがなく、挙動が変わらない。
  `scripts/StrykerSummary.cs` が自動で除外する。Stryker の `ignore-methods` で除外しないこと
  （待機している呼び出しの中の本物の変異まで消える）。
- `GC.SuppressFinalize(this)` の削除: ファイナライザがないクラスでは影響しない。
- null ガードの削除で、直後の呼び出しが同じ `ArgumentNullException` を投げる場合
  （LINQ の `Distinct()`、DI の登録メソッド、`Dictionary.ContainsKey(null)` など）。
  ガードがないと `NullReferenceException` になる場合や、遅延評価（`yield`）で例外の時点が変わる場合は**等価ではない**。
- 到達しない右辺: `x.ToString() ?? string.Empty`（値型や非 null の型）など。
- 結果が同じになる分岐: `errors.Length == 0 ? Success() : Failure(errors)` で、空のエラーの Failure が Success と等しい場合。
  早期 return を消しても、続きの処理が同じ結果を返す場合。
- 直前のアサーションで存在が保証された後の `First()` → `FirstOrDefault()`。
- ログやエラーメッセージ内の文字列の変異（メッセージ自体が仕様でない限り）。
- 後続の破棄で同じ結果になる処理: トランザクションの `Rollback` を消しても、`Dispose` / 接続の破棄で暗黙にロールバックされる。
- キャッシュの `??=` → `=`: 毎回作り直すだけで結果は同じ。
- フレームワークが例外を包む場合: System.Text.Json はコンバータ内の `InvalidOperationException` を `JsonException` に包む。
- 同じ例外をフレームワークも投げる場合: 自前の「二重開始チェック」を消しても、EF Core が同じ型の例外を投げる。

## 未計測（Stryker の誤判定）の既知パターン

Stryker は全変異を 1 つのアセンブリに埋め込み、実行時に切り替える。プロセス内で一度しか実行されないコードは、
切り替える前に実行済みになり、変異が効かない。

- static フィールドの初期化子、static コンストラクタ。レポート JSON で `static: true` になる。
- static 初期化の中から呼ばれるインスタンスコード（例: 派生クラスの static フィールドで生成される値の、基底クラスのコンストラクタ内の登録処理）。
  `static` フラグは付かない。**実行のたびに生き残る箇所が変わる**のが目印。
- EF Core のモデル構築（規約、`OnModelCreating`、`ConfigureConventions`）: モデルはプロセス内でキャッシュされる。
- アナライザの `RegisterCompilationStartAction` の中（規則を登録するかどうかの早期 return など）。
- その他、初回アクセス時にプロセス全体でキャッシュされる処理（シングルトンの遅延初期化など）。

確かめ方: 該当箇所を手で書き換え、その変異を検出するはずのテストを含むテストプロジェクトだけを実行する
（`dotnet test --project tests/<Foo.Tests>`）。終わったら必ず `git restore <ファイル>` で元に戻す。
テストが失敗すれば「未計測」、通れば本物の穴か等価として分類し直す。

## 到達しないコードの例

- 診断が出ない状態に対するコード修正の分岐（例: 修飾子のないコンストラクタはもともと private で、診断が出ない）。
- 防御的な早期 return（構文ノードが見つからなかった場合など）。

到達しないことは、呼び出し元の条件をたどって確かめる。到達しうるならテストを書く。

## 記録の形

報告では、除外した変異を表にする。

| ファイル:行 | 変異 | 分類 | 理由 |
|---|---|---|---|
| `Foo.cs:42` | `ConfigureAwait(false→true)` | 等価 | 同期コンテキストがない |
| `Bar.cs:10` | 文の削除 | 未計測 | 手で入れて KILLED（モデル構築時のみ実行） |
